# 本轮文献核查

[Trap² 原文](https://arxiv.org/html/2601.21898v2)正文提供[官方代码](https://github.com/ml-postech/Trap2)。它通过训练保持原尺度的任务能力，同时提高任务更新缩放后的损失；不是免训练后处理。本项目不执行其优化，也不把该思想改名为新方法。

[固定源码核对](trap2_source_audit.json)检查了完整参数版本的训练入口：缩放权重、两项损失、反向传播和优化器更新都存在，已记录 commit、文件指纹及行号。

该论文可以帮助我们检查机制是否充分，但不能提供现有补空间噪声的安全保证。其跨专家损失分析还依赖融合路径上的方向曲率；参数距离大本身不保证性能崩溃。目标至基座的缩放路径也不能替代真实伙伴融合、AGA 和公开清理测试。

附录 A.2 的正损失下界需要路径曲率足够大且名义点梯度足够小；A.4 需要真实融合方向的条件。固定公开投影把保护和原专家映到同一状态时，清理前的曲率不能提供清理后的保护保证。详细条件与本项目推论见[机制分析第 5 节](../../notes/mechanism_analysis.md)。

NUFILT 的近似对齐也不能把低维数据流形直接等同于固定低秩激活空间，更不能保证任意大的补空间噪声保持分类。已有 block 5 数据只支持近似截断，不支持该处存在大规模精确零空间。

本轮没有可信的新权重构造。下一步核对投影仅能估计时的恢复边界：分别分析保持误差、清理误差和发布权重中的可识别方向；复用已有矩阵，不重跑已关闭的防御、不扫参数。
